# 安睡声迹 SleepScope · Android 本地睡眠声学日志

一个简洁的原生 Android 睡眠声学记录应用，**不联网、不上传声音、只在手机本机保存**。默认仅录制疑似鼾声及人声候选事件对应的短 WAV 片段。

## 已实现的功能

- 点击「开始睡眠监测」后，申请麦克风权限并启动 `microphone` 类型前台服务。
- 持续读取 16kHz/PCM16/单声道麦克风数据，进行**本地声学启发式分类**（疑似鼾声、疑似人声/梦话、其他声音、安静）。检测阈值可在设置中调整。
- 每个符合阈值的事件保留约 2 秒前置声音及后续声音，按 WAV 片段保存（每段不超过约 35 秒，单次最多 350 段、累计 WAV 约 120MB 上限）。
- 记录部分**两段疑似鼾声之间的长时间安静间隔**（10–90秒、安静比例至少70%，且中途无明显其他声音）；显示“声音间隔观察”，**不作为真实呼吸暂停测量**。
- 持续保留通知，支持锁屏后台录制和通知栏主动结束；服务持有 `PARTIAL_WAKE_LOCK` 保持 CPU 运行。
- 自动画夜间声学事件分布柱状图；查看某晚监测时间、疑似鼾声/人声次数、声音间隔、各 WAV 片段。
- 播放事件录音、通过系统文件选择器**主动导出**某一段 WAV、分享纯文字报告、删除整晚的私有数据。
- 每约20秒检查点保存数据，即使意外中断也可能保留此前的数据；**不保证因系统强杀或断电而恢复完整监测**。
- 默认完全离线：无服务器、无登录、无 INTERNET 权限。

## ⚠ 医疗安全与准确性边界

本 APP 不能通过手机麦克风准确判断是否处于睡眠，也**不能诊断、确认或排除阻塞性睡眠呼吸暂停（OSA）**。在没有鼾声的正常呼吸期间，手机也可能几乎听不见任何声音；“声音间隔观察”的次数和秒数不能换算为呼吸暂停次数、AHI 或暂停时长。

“梦话”识别也是对疑似人声的**简单声音特征筛选，不是语音识别或说话人识别**；电视、家属声音、宠物等可能误报。若有明显打鼾、目击呼吸停止并突然猛吸气，应到耳鼻喉科或睡眠医学科进行多导睡眠监测或医生指定的规范检测，不应依赖该 APP 的数据做医疗决定。

## 技术栈

- Android 原生 Java，Android Gradle Plugin 8.7.3；Gradle 8.9；JDK 17。
- minSdk 26 / compileSdk 35 / targetSdk 35（Android 8.0+；适用于 Android 16）。
- **零第三方运行时依赖**；JUnit 仅用于本地测试。
- `AudioRecord` 连续输入、Goertzel 频谱粗估、时域周期性、分类聚合、标准 WAV 文件头。
- `Service` + 常驻通知 + `PARTIAL_WAKE_LOCK`；会耗电，建议整夜充电并按机型设置应用电池不受限。

## 如何生成 APK

### 方式 A：GitHub Actions（无需本地安卓开发环境）

1. 在 GitHub 新建私人仓库（Private），把本压缩包解压后的文件上传到仓库根目录，保持 `.github/workflows/build-apk.yml` 路径。
2. 打开仓库 → Actions → **Build Android APK** → Run workflow（或推送到 `main`/`master` 自动触发）。
3. 构建成功后，打开该 Actions 运行记录，在 **Artifacts** 下载 `SleepScope-debug-apk.zip`；解压得到 `app-debug.apk`。
4. 将 APK 发送到安卓手机，在系统提示下允许安装此来源的应用并完成安装。

> Debug APK 会由 GitHub runner 的临时 debug key 签名。每次使用不同 runner 编译安装的 APK，签名密钥可能变化，需要先卸载旧版本（备份/导出所需录音后再卸载）。要长期无损升级，应配置自己的固定发行签名。

### 方式 B：Android Studio

1. 在电脑 Android Studio 打开本项目根目录，安装 Android SDK Platform 35、Build Tools 35.0.0、JDK 17 与 Gradle 8.9。
2. 选择本地 Gradle 8.9，或先运行 `gradle wrapper --gradle-version 8.9` 生成标准 wrapper jar。
3. Gradle 同步完成后，执行 `:app:assembleDebug` 或 Build → Build Bundle(s)/APK(s) → Build APK(s)。
4. 文件在 `app/build/outputs/apk/debug/app-debug.apk`。

> 当前交付包是**工程源码，不含经本环境实机验证的 APK**。CI 工作流用于自动编译成 APK。真实背景录音必须在目标手机上连续测试至少一整夜。

## 建议在手机上做的验证

1. 首次启动允许麦克风权限，并建议允许通知。
2. 点开始，确认系统录音绿色提示和“安睡声迹 · 正在监测”常驻通知。
3. 熄屏等待 3–5 分钟、重新点亮屏幕，确认总时长继续走动且通知仍在。
4. 用模拟鼻鼾声和人声短片段进行试录，结束后检查事件数、WAV 播放和导出。
5. 一整晚连接充电器，设置系统电池 → 安睡声迹 → **不受限**（具体菜单以手机型号为准）；晨起检查是否被系统中断。
6. 有家属观察到呼吸暂停/憋气者，优先就医接受规范睡眠呼吸监测。

## 隐私

- 录音保存在系统私有目录 `filesDir/sleep_nights/<时间戳>/clips`。
- 不申请网络或外部存储权限。
- 文件只有用户在「导出录音」时才由系统文件选择器输出；文字分享需要明确触发。
- 卸载应用通常会删除本地数据，**建议提前主动导出重要录音**。

## 边界与待优化方向

本版本未实现训练后的 AI 鼾声识别模型、睡眠分期、心率、血氧采集或真实呼吸暂停检测；如果未来需要医学级睡眠呼吸事件判定，应依赖有临床证据的呼吸气流/胸腹运动/血氧等数据源，并完成相应验证。
